# 手绘素材与 SVG 素材对比分析（修正版）

参照母版改为用户提供的真母版 `Peizheng-Live2D-reference/P1-master-true.png`（1254×1254，919,689 字节）。

此前误把 `P1-master-no-hands.png` 当作母版，那是我生成的重绘稿，带多层渐变和高光，不是用户的原图。基于它得出的"缺渐变""1:24:95 细节差距"等结论作废。

## 一、真母版的实际风格

平涂 + 粗描边。贝雷帽是深蓝主色加一条浅蓝高光带，头发是大块红色加简单分缕，眼睛是紫色圆加白色高光点，钟楼是红顶、米色墙、圆形钟面。没有多层渐变，没有复杂阴影。

按此标准，SVG 用平涂几何图形表达角色，风格方向是对的，问题出在完整度和轮廓精度。

## 三、两版素材的真实差距

### 手绘 hat.png

结构和配色与真母版高度接近，钟楼、紫花、缎带都对上了，平涂粗描边的风格也一致。手绘在圆扣上补了校徽图案，这是手绘稿的最终设计，以手绘为准。钟楼大小和紫花位置与母版有出入，同样以手绘版本为准。

### SVG hat.svg

只画了贝雷帽的帽檐弧线、红白缎带和圆扣。钟楼、紫花、校徽三个标志性元素全部缺失，是半成品。帽檐的弧度也比母版窄，贝雷帽的浅蓝高光带没有单独表现。

### 其他部件

`body.svg` 用 11 条硬编码的二次贝塞尔路径画完整件制服，`side_L.svg` 只有 2 条路径。手绘 PNG 是在这些路径基础上继续修的，文件时间和体积都能看出手绘是后补的。

## 四、修正后的工程缺陷

1. **SVG 源稿不完整**：程序化绘制只覆盖了基础形状，钟楼、紫花、校徽这类标志性元素完全依赖后期手绘补。`hat.svg` 交付时只有一半的帽子。
2. **SVG 没有跟上手绘的修改**：手绘在圆扣上补了校徽，钟楼和花的比例也做了调整。手绘是最终标准，SVG 源稿没有同步这些修改。
3. **源稿与成品双轨脱节**：手绘修正没有回写 SVG，`draw.cjs` 一旦重跑就会用旧几何覆盖 PNG，钟楼、紫花全部丢失。
4. **验收只查数量不查形**：流程校验 attachment 数、动画条数、图片尺寸，从不校验部件轮廓与母版的偏差。`bounds.json` 只保证贴图位置，不保证形状。
5. **颜色数不能单独当指标**：真母版帽子区域 23,094 色，手绘 27,350 色，两者接近。SVG 只有 1,156 色，主要因为它是纯色块渲染，抗锯齿少，不代表风格错误。判断匹配度要看轮廓、比例和元素完整度。

## 五、结论

手绘素材是最终标准，与真母版的整体结构一致，校徽等细节属于手绘的主动设计。SVG 素材的问题是只画了基础形状、缺标志性元素，属于半成品级别。工程上真正敷衍的地方在于：用几何路径占位，把关键元素留给后期手补，又没有让 SVG 跟上手绘的最终设计，最后把「能打包、能播动画」当成了「已完成」。
